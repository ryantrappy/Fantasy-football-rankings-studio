# Fantasy Power Rankings

One React 19 / TanStack Start application serves the UI, authenticated server functions,
Sleeper/ESPN adapters, and MongoDB persistence. Node.js 22.12+ is required.

## Run locally

```sh
npm ci
test -f .env || cp .env.example .env
# Fill in Auth0 settings, MongoDB URI and private ESPN cookies in .env.
npm run dev
```

Open http://localhost:3001. MongoDB must be running. The legacy `fantasy_server`
project is no longer used. See [LOCAL_SETUP.md](../LOCAL_SETUP.md) for first-machine
setup, Auth0 configuration, provider test IDs, and verification details.

## Production

```sh
npm run build
npm start
```

Start uses Vite for compilation and Nitro's Node adapter for one production request
handler. Deploy the entire `.output` directory and run `.output/server/index.mjs`
with the server environment set. The local `npm start` command loads `.env` and
`.env.local` and defaults to port 3001; override with `PORT=8080 npm start`.
Public `VITE_*` settings are embedded at build time, so rebuild when they change.

## Architecture

- `src/routes`: Start document, routing, session boundary, editor, creation page and `/health`.
- `src/functions/rankings.functions.ts`: typed Start RPCs, replacing all Express endpoints.
- `src/server`: JWT verification, runtime validation, provider adapters, services and Mongo models.
- `src/api/client.ts`: per-account TanStack DB collections backed by TanStack Query and Start RPCs.
- `src/components/CreateLeague.tsx`: TanStack Form; ranking editor retains serialized autosave and navigation flushing.
- `src/auth/Authentication.tsx`: browser Auth0 session; every private RPC independently validates the access token and ownership.
- `server/plugins/database.ts`: closes MongoDB connections on production shutdown.

TanStack DB manages reactive client collections; MongoDB remains the durable server
store. Existing leagues and rankings use the same database and collection names.
Database and provider secrets remain server-only. Authenticated collections are
created separately for each session and cleaned up when it changes. Confirmed
server writes update the corresponding collection; failed writes preserve the draft.
Private RPC responses disable caching. No CORS proxy or separate API port is needed.

The document and loading shell render on the server; authenticated data loads after
the browser restores its Auth0 session. `src/routeTree.gen.ts` is generated by Start
and should be committed. Do not edit it manually.

## Verification

```sh
npm test
npm run typecheck
npm run lint
npm run format:check
npm run check:local
```

`check:local` builds and runs a separate disposable instance of the production app,
verifies signed JWTs over HTTP, reads live Sleeper/ESPN data, tests ranking writes,
reloads and ownership isolation, then drops only its randomly named test database.
It uses a temporary local JWKS issuer; the real application retains Auth0 validation.
Set `TEST_PORT` if port 3101 is busy, or `TEST_SEASON`, `TEST_SLEEPER_LEAGUE_ID`, and
`TEST_ESPN_LEAGUE_ID` to change the provider fixtures.

Provider records are season-to-date, not reconstructed historical weekly records.
Weeks currently use 1–18. ESPN private cookies are deployment-wide. The existing
ownership model allows one account per external league ID; sharing, per-user
provider credentials, and cross-provider ID collisions are not part of this migration.

## Season insights

Open `/insights` from the main navigation. League and season selections are encoded
in the URL. The authenticated Start function reads only leagues owned by the current
account; TanStack Query caches results per session for five minutes, with a manual
refresh. TanStack Charts renders weekly actuals and available projections, with
exact values in an accessible table.

The page includes scoring averages, best weeks, weeks above the league median,
actual-vs-projected trends, individual trade assessments, and normalized pickup rankings.
Trades compare received versus sent player packages over a shared four-week window
following the reported transaction week. Each player's value is scoring above the
median of at least three other league starters at the same position. Package values
are summed and expressed per week; rostered bench player scoring is included, so
lineup selection and the time a player was subsequently held do not decide the grade.
A scoring leader requires at least two common weeks, 75% coverage of the completed
window, and more than a one-point/week gap between the leading net gains. Draft-pick
trades receive no overall winner call. These are scoring assessments, not causal or
long-term dynasty valuations.

Pickups rank by average lift per start in the first four post-acquisition weeks,
ending before the next move. A clean same-position pickup/drop pair uses the dropped
player's observed scores when coverage is complete for at least two starts. Otherwise,
one consistent positional starter-median baseline is used. Missing scores or positions
are not zero-filled; the UI shows the actual baseline and compared weeks. Only roster
snapshots are observed; unrostered players may be unavailable. Sleeper positions come
from its current player catalog; ESPN uses each historical box score's primary position.

Sleeper uses linked historical seasons and the league's last scored week. Its
[documented API](https://docs.sleeper.com/) does not supply historical projections;
that section shows actual points and median comparisons. ESPN reads saved lineup
projections and weekly box scores, excluding bench/IR. Missing projections stay
missing. Only completed weeks are included, so a new season has an explicit empty
state. Partial lineup coverage is disclosed rather than counted as zero.

The local integration check also exercises both leagues' 2025 insights and verifies
ownership denial. Override this historical fixture with `TEST_INSIGHTS_SEASON`.
